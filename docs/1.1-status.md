# CapsLang 1.1 — состояние реализации

## Исправление ошибочного первого этапа

Работа в ветке `4erk/capslang-1.1.0`, база приложения — `cb547dc` (1.0.0).

- Прежняя интерактивная диагностика отозвана: её код остановки CapsLang,
  произвольной длительной паузы, ручного выбора окон и записи LED удалён.
- Вместо неё собирается **только читающий** `CapsLangInventory.exe`.
- Добавлен автоматический тест на отдельном неактивном Windows-desktop:
  реальные межпроцессные запросы, фактическая раскладка, отказы, задержки и UIPI.
- Исправлен запуск native EXE в build.ps1 при унаследованном PATHEXT=.CPL.
  Переменная восстанавливается; системные настройки окружения не меняются.
- Исходники основной программы 1.0.0, установленный EXE и Run-запись не изменены.
  SHA-256 установленного EXE:
  `C1AC033D4409F1DD54AC1C542D21A25EDAAE0AB911A80A389AE1FD6409AB138F`.

## Проверено на ноутбуке 2026-09-28

- 20 unit-проверок вспомогательной логики и 15 platform-precondition проверок.
  Они не засчитываются как приёмка MWB.
- 36 интеграционных проверок с реальными процессами Windows проходят.
  Прямой EN/RU работает на обычном тестовом окне без Win+Space.
- Повторный прогон: 20 запусков этого набора, 400 последовательных смен EN/RU,
  без сбоев. Это не стресс физической клавиатуры и не переходы между ПК.
  SHA-256 тестового EXE:
  `F32A14704FA7FC8A30C33AE51C7DBABDC7E2F1F923E4F0C087B7BA13C1373DB8`.
- Low Integrity процесс не может отправить запрос обычному окну:
  WM_INPUTLANGCHANGEREQUEST и контрольный WM_APP возвращают error 5.
- PostMessage может вернуть успех при отказе приложения менять язык —
  это воспроизведено, а не предположено.
- Первоначальные layout-тесты не меняли LED. Результат последующей отдельной
  проверки записи и восстановления приведён ниже.
- 4ERK-PC разрешается в LAN. Проверенные SSH (22) и WinRM (5985) недоступны.
  Двухмашинные тесты не выполнены. Удалённые службы и firewall не включались.

Первый повышенный запуск завершился `Access denied` до появления процесса
теста и отчёта; он не засчитан. Во время ожидания UAC изменяемый EXE был
пересобран — это выявленная ошибка организации запуска, возможная причина
отказа, а не доказанный диагноз Windows. Обязательная проверка подписи в UAC
выключена; совпадающих событий блокировки в доступных журналах не найдено.
Повторный запуск выполняется через `tests\run-elevated.ps1` из уникальной
копии с проверкой SHA-256. Настройки защиты не меняются.

Повторный запуск завершился успешно: `elevated=true`, 36 проверок, 0 ошибок,
exit code 0. SHA-256 тестового EXE до и после запуска совпадает с указанным
выше. Проверены собственные повышенные Win32-окна на изолированном desktop,
включая смену EN/RU без Win+Space. Это подтверждение работы примитива в таком
окружении, **не проверка проблемного системного диалога или всех приложений**.
Подпись EXE отсутствует (`NotSigned`); предупреждение об неизвестном издателе
не помешало этому запуску. Подпись не добавлялась, защита Windows не отключалась.

## Подтверждённый блокер синхронизации

Прежний observer ошибочно считал служебную инъекцию движения MWB реальной
активностью. Его предикат больше не называется IsDeliveredActivity и не может
использоваться для выбора авторитетного состояния. Подробности и исходники
MWB: [инженерные проверки](1.1-feasibility.md#обнаруженный-дефект-определения-получателя-mwb).

## Реализованные компоненты следующего этапа

Это компоненты разработки, **не интегрированное приложение 1.1**. Основной
`src/capslang.cpp`, установленный EXE, Run-запись и процесс 1.0.0 не изменены.

- `src/core`: согласованное подавление Caps down/up, удержание и Shift;
  абсолютный EN/RU, latest-wins generation, ограниченные повторные попытки,
  отдельные события фокуса/пользователя/пары, блокировка desktop.
- `src/runtime/engine`: настоящий отдельный hook-поток и worker, проверки
  фактического HKL, периодическое обновление hooks без F24, уведомления питания
  и сессии. Ни hook callback, ни новое ядро не вызывают SendInput.
- `src/runtime/local_ipc`: фиксированные Status/SetLayout/RefreshHook/Stop,
  ACL текущего SID, проверка сессии клиента, запрет удалённых клиентов,
  проверка пути/прав сервера клиентом, лимиты сообщений и времени ожидания.
  Установочный код должен передавать защищённый путь Program Files: самого
  установщика пока нет; test-policy явно разрешает свой тестовый EXE.
- `src/network/tls`: взаимный Schannel TLS 1.2, RSA-3072/SHA-256,
  обязательное pinning точного сертификата обеих сторон, ограниченные буферы
  и ожидания. Тесты используют только loopback. Временные собственные CNG-ключи
  удаляются владельцем после теста; доверенные корни и firewall не меняются.
  Постоянное хранение пары, приглашения и протокол общего состояния ещё не
  подключены. Это не готовая синхронизация двух компьютеров.
- `src/platform/mwb`: read-only источник **кандидатного** routing-признака
  по служебному 4×4 layered окну Helper. Проверяются конкретная версия и
  подпись Microsoft; заголовки окон не читаются. Неопределённость не считается
  локальной активностью. Обычный процесс здесь получает error 5 при проверке
  повышенного Helper; WTS правильно показывает два приложения и один Helper,
  вместо ложного вывода «MWB выключен». Подпись файла Helper отдельно Valid,
  версия 0.101.2362.0. Этот источник пока **не авторитет для синхронизации**.

### Автоматические результаты

Команда: `./build.ps1 -RuntimeTestsOnly`.

- Core: 430 проверок чистой логики, не физической клавиатуры.
- Engine/Windows: 95 проверок, включая два настоящих иностранных процесса,
  точный язык, очередь запросов, фокус, реальную регистрацию/обновление hooks,
  завершение потоков и IPC из отдельных medium/low-integrity процессов.
  Medium-клиент разрешён, low-клиент получает error 5. Обычный прогон проверяет
  medium-сервер; для границы medium → elevated требуется повышенный прогон.
- IPC: повреждённые magic/version/operation/flags, неверный язык, подмена пути
  и прав сервера, запрет anonymous SID, коллизия имени pipe, idle-client timeout,
  короткие/слишком длинные сообщения, завершение/перезапуск.
- TLS: 11 проверок с реальными сокетами и Schannel. Восемь двусторонних
  зашифрованных обменов; неверный pin сервера и чужой сертификат клиента
  отвергаются с SEC_E_WRONG_PRINCIPAL. Пустой pin не включает TOFU.

Новый regression-тест действительно воспроизвёл ошибку: отложенное на 180 мс
старое RU после нового EN принималось за ручную смену. После добавления окна
защиты собственного применения тест проходит. Эта защита ограничена 1500 мс;
произвольно поздние ответы и ручной Windows selector во время этого интервала
**не подтверждены**. Успех этого теста не закрывает весь manual/focus gate.

### LED: фактическая запись/восстановление

Отдельный opt-in тест выполнил SET → QUERY → восстановление → QUERY без
синтетических клавиш и без остановки 1.0.0. Один class endpoint подтвердил
изменение и восстановление; четыре не поддержали операцию (87 либо 50).
У трёх из них SET формально возвращал успех, но QUERY не менялся — рабочий
`SetScroll` теперь тоже проверяет обратное чтение и сообщает ERROR_NOT_SUPPORTED.
Состояния Caps/Num/Scroll в очереди теста до и после совпали.
Это **не оптическая проверка LED нужной физической клавиатуры и не приёмка ПК**.

### Повышенное ядро — отдельный незавершённый gate

Запрошен UAC для неизменяемой копии `windows_engine_integration.exe`:
SHA-256 `DCDCD19B773963163572682CFCCA0CBCD149BC8DEAB43933ED63629AA0736442`.
Копия находится в `build/elevation/c7f68f792d99445fa4ff135c308eba05/`.
На момент записи подтверждение UAC ещё ожидается; успешный результат не заявлен.
Этот запуск включает read-only MWB metadata и затем изолированный тест ядра,
не устанавливает программу, не меняет рабочий desktop или автозапуск.

## До приложения и релиза остаётся

- Подтвердить настоящего получателя MWB при обоих порядках hooks и неоднозначных
  служебных инъекциях; кандидатная видимость Helper не заменяет этот gate.
- Закрыть manual-selector/focus/late-ack сценарии, реальные полные клавишные
  последовательности и потерянный key-up. Физический RawInput release пока не
  подключён; тест обновления hook без ввода не доказывает все held-key случаи.
- Изолировать/ограничить зависание драйвера LED (IOCTL пока синхронный),
  подтвердить индикатор обеих используемых клавиатур.
- Интегрировать broker и elevated engine в распространяемый EXE; добавить
  постоянные защищённые данные пары, приглашения, LAN-канал общего состояния,
  разрешение конфликтов/переподключений, пользовательский интерфейс и журналы.
- Защищённая транзакционная установка, задача планировщика, firewall-правило,
  миграция/rollback, полная совместимость CLI и тесты сбоев установки.
- Двухмашинная приёмка, 2 часа/100 переходов, затем RC и стабильный выпуск.

**CapsLang 1.1.0 не готов; RC и стабильный релиз не опубликованы.** Согласованный
план пока не выполнен; количество проверок отдельных компонентов его не заменяет.
