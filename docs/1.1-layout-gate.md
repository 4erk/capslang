## Reproducible diagnostic

`tools/build-layout-gate.ps1` builds a standalone development executable using
the already pinned LLVM-MinGW 20260616 toolchain. Two builds produced SHA-256:

`6690f0e83a69e65f2ff3a369daf4bbc6f2ad5fd14b712c2ed62a3fcade9d81d3`

Default invocation is read-only. `--apply EN|RU` is rejected with error 87 unless
`--confirm-active-desktop` is present. The executable installs no hooks, injects
no input, reads no window text and makes no registry/settings changes.

Samples deliberately distinguish the diagnostic thread's TSF profile and
language, foreground thread HKL, and shell thread HKL. None is labelled as
verified taskbar pixels. `visual_indicator_verified` is always false.

The medium-integrity runner supports an explicitly opted-in bounded live test:
stop installed CapsLang, run the diagnostic, restart the installed application
in `finally`, record the result. It does not replace the installed executable
or modify its startup tasks. A hung owned child is terminated, not a user app.
The runner is not a crash-proof watchdog; killing the runner/host itself is not
a supported acceptance scenario. Reports use CreateNew, so a retry cannot
overwrite evidence from an operation with an unknown outcome.

Example (ordinary PowerShell, from the repository; choose a new report name):

```powershell
.\tools\build-layout-gate.ps1
.\tools\run-layout-gate.ps1 -Executable "$PWD\build\layout-gate\CapsLangLayoutGate.exe" `
```

## Interpretation and remaining acceptance

that a foreign foreground thread has switched. This is a concrete failed
cross-thread observation, not yet an optical measurement or a typing test.
Do not claim the diagnostic's GetActiveProfile result is a global OS profile.

The user confirmed both screens were available and was asked whether PC's
native indicator changed to RU without cursor transfer/click during the test.
The user did not catch the first visual interval; it is explicitly not accepted
as a visual pass or failure. A repeat began at approximately 16:16:32 UTC,
requesting the same RU in four bounded 30-second rounds. During that interval
the user explicitly answered **EN** for PC's native indicator without moving
the mouse there. The diagnostic was then stopped early (only its exact owned
child) so the runner could restore RC1 in finally. Early termination is
intentional, not a spontaneous crash of the candidate.

A third run started at 16:19:29 UTC after the user explicitly confirmed the
baseline NB=RU / PC=EN and asked to start while watching. The user again
confirmed **"remains EN"** during the running test. This removes the missed

`gate-apply-ru-6690-repeat.jsonl`. Both use the same verified diagnostic EXE.

The native-indicator requirement has therefore failed this proposed mechanism.
