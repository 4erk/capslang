# CapsLang 1.1 — состояние реализации

## Выполнено: инструменты первого проверочного этапа

- Ветка `4erk/capslang-1.1.0`, база `cb547dc` (1.0.0).
- Отдельный неустанавливаемый `CapsLangProbe.exe`, собранный тем же закреплённым
  LLVM-MinGW. Сборка с `-Werror`; 34 новые автоматические проверки проходят.
- Две чистые сборки probe побайтно совпадают. SHA-256:
  `81B8C7EF0E761B00B59A4B14C6A4B532C9F72E750AB18AB8D6A29973C01B9284`.
- Реализованы проверяемые примитивы: TSF/адресная установка EN/RU, чтение
  фактического языка целевого потока, определение прав, чтение/запись LED через
  IOCTL с сохранением других битов и observer ввода без регистрации клавиш.
- Локальная безопасная инвентаризация подтвердила EN/RU и успешное открытие /
  чтение индикаторов устройств. **Это не подтверждение физического LED.**
- UI позволяет на время проверки остановить точный установленный экземпляр
  1.0.0 и восстановить его из обычного процесса. Автозапуск не изменяется.
- Исходники приложения 1.0.0, установленный EXE и стабильный релиз не заменены.

## Ожидается живая проверка — не считать выполненным

- Обычный и повышенный проблемный диалог: фактическая смена EN/RU и возврат.
- Scroll Lock LED на обоих компьютерах; отсутствие изменений Caps Lock, Num
  Lock и логического Scroll Lock.
- Определение реального получателя ввода при обоих порядках установки hooks;
  отдельное внимание служебным перемещениям курсора самим MWB.

Инструкция: [1.1-feasibility.md](1.1-feasibility.md). Сырые отчёты
`capslang-probe*.jsonl` игнорируются Git и не публикуются.

## Следующие этапы после успешной проверки предпосылок

1. Новое приложение: непривилегированный broker, повышенный локальный engine,
   ограниченный IPC, безопасное восстановление hooks и явные power/session
   notifications. Замена Win+Space и F24, глобальный EN/RU, аппаратный LED.
2. Сопряжение через Schannel, защищённое хранение доверия, LAN-соединение,
   версия состояния/дедупликация, активность и согласование после разрыва.
3. Защищённая установка с UAC, задачи планировщика, ограниченный firewall,
   миграция 1.0.0, rollback, интерфейс и служебные команды.
4. Интеграционные и негативные тесты, prerelease `v1.1.0-rc.1`, затем живая
   двухмашинная приёмка (включая двухчасовой прогон и 100 переходов).
5. Только после приёмки — стабильный `v1.1.0`.

Ни IPC, ни сеть, ни установка 1.1, ни release candidate на этом этапе ещё
**не реализованы**. Не переименовывать probe в `CapsLang.exe` и не устанавливать
его в автозапуск. При провале предпосылки сначала согласовать изменение решения,
а не заменять её другим способом без уведомления пользователя.
