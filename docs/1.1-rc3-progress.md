# RC3 — проверка и доставка, 2026-10-08

Ветка `4erk/capslang-1.1.0`, кандидат `1.1.0-rc.3`. Новая функция — исправление
раскладки выделенного текста Ctrl+CapsLock. Скачивание остаётся одним EXE;
встроенные x64/x86 модули распаковываются по хешу в защищённую папку.

## Подтверждено до финальной сборки

- Пользователь подтвердил преобразование в Opera на ноутбуке.
- Уточнено правило: направление из выделения, не текущей раскладки;
  смешанный текст меняется в обе стороны, без смены общего языка.
- Повторная ручная проверка этого правила в Opera: «работает».
- Обе машины временно получили одинаковый диагностический EXE
  `E9D554CA4F5374398E346BE2641394C5DC622BFB9FFCA2E01EB0825D2D6F3A9B`.
  Пользователь подтвердил проверку Ctrl+CapsLock на ПК через MWB, со сменой
  языка обоих устройств после замены: «работает».
- Координаторы NB 12720 и PC 13404 завершились кодом 0; прежний установленный
  EXE и зашифрованные файлы пары сохранены, задачи/служба восстановлены,
  временные задачи и правила удалены. Временное правило передачи файлов также
  удалено. Эти результаты не являются постоянной установкой RC3.
- До смены версии: core 515, SYSTEM protocol 131120, profile channel 62,
  Windows integration 237, application 348 и остальные RuntimeTestsOnly — зелёные.

## Доставка

Готовится финальная Release-сборка без диагностического режима, с повторением
тестов и второй чистой сборкой для сравнения SHA-256. Установка обоих устройств
использует штатную административную транзакцию и обычный координатор миграции;
сопряжение не пересоздаётся. Проверки доставки фиксируются ниже по результатам.

Не завершённые проверки стабильного выпуска перечислены в [состоянии 1.1](1.1-status.md).
RC3 публикуется как prerelease. Непроверенная длительная приёмка не выдаётся
за выполненную физическую работу.

## Публикация и установка

Опубликован публичный prerelease [v1.1.0-rc.3](https://github.com/4erk/capslang/releases/tag/v1.1.0-rc.3)
из `2598ee2c6f1e7f71b3425998900b95be2a0046b3`: EXE, SHA256SUMS и инструкция.
Повторное скачивание опубликованного EXE совпало побайтно с локальным.

На 4ERK-PC опубликованный EXE скачан с GitHub и установлен: административная
транзакция и обычное завершение миграции — code=0 (координатор 23008).
На 4ERK-NB первая транзакция вернула code=2, abort=0. Файл RC2 и прежняя служба
восстановились, но задача engine закончилась с code=2; здоровый запуск ролей
при откате автоматически не подтвердился. После отдельного запуска той же
проверенной задачи Engine она стала Running. Проверка --layout-check к тому
моменту завершалась успешно. Повторный контролируемый update завершился
admin=0 / complete=0 (6152). Это не доказательство исправления гонки установщика.

В коде начальная проверка --layout-check проверяет канал layout, а SYSTEM worker
создаёт profile/Caps каналы после него; EngineHost требует готовности Caps после
первого poll. Это вероятное объяснение отказа раннего запуска, но детерминированное
воспроизведение и исправление остаются задачей перед стабильной 1.1.0.

Оба установленных EXE имеют версию RC3 и SHA-256
`E13B6370D181BF0340B7FA4B3736FD4653AB233BD0D317021A99EBE7E036B5AC`.
На обеих машинах проверены неизменность зашифрованных identity/pair, резервный
EXE RC2, Running штатной SYSTEM-службы и двух задач. Финальные проверки статуса
(NB 16692, PC 20604) завершились code=0: свежий RC3, готовый hook, подтверждённый
профиль, Active защищённое соединение, подтверждение второго устройства.
Старый Screensaver Guard остаётся Running на обеих машинах; его миграция не
выдаётся за выполненную. Финальный установленный бинарник не проходит повторную
двухчасовую физическую приёмку в рамках этой записи.
