# RC2 development checkpoint — 2026-10-06

Branch: `4erk/capslang-1.1.0`. Not a release or installation claim.

## Implemented, still undergoing review

- Fixed-operation local SYSTEM service/worker, current installation owner and
  console session, Default/unlocked desktop, authenticated local same-image
  elevated clients, no networking. Owned workers have bounded recovery.
- Installer service lifecycle journal, RC1 status/stop compatibility only,
  restoration of the previous installation's service presence on rollback.
- IPC v4 and peer-session v2; absolute language application and generation-bound
  profile reports. Old/failed/expired confirmation cannot retain Applied.
- Retained desired target and bounded retry after a failed engine/queue attempt.
- Runtime MWB process presence instead of pointer-recipient correlation.
- Removed the hardware LED implementation and its obsolete tests. Old tracked
  source is recoverable from Git; no installed legacy binaries were deleted.
- Technical state-change logging now includes target, actual, generation,
  revision, application and peer confirmation changes.
- Extracted `runtime/thread_profile.*` from the experiment: target-thread TSF
  subscription, actual/profile readback, generation-bound EN/RU application,
  reentrant cancellation and invalidation after an external change. It runs
  through the production module/attachment code and the optional module-backed
  engine branch. The ordinary installed entry point is not switched over yet.
- Local IPC optionally pins both ends to a kernel-derived process ID **and
  creation time**, retaining the existing SID/session/image/elevation checks.
  The new module's fixed local protocol is defined separately from the peer
  protocol (v2, local QPC ordering); private worker/queues are implemented.
- Added the same-bitness, per-thread hook owner and installed DLL entry point.
  Bootstrap carries only a nonce, not commands or paths. The private pipe
  authenticates SID/session/image/elevation and pins kernel process incarnation;
  owner loss is handled by the module's timer even after removing its hook.
- Embedded x64/x86 modules inside the development EXE. Installer stages both
  validated modules in protected hash-addressed directories before stopping the
  old version, preserving previous loaded module files for rollback. Actual
  elevated install/rollback of this bundle has not yet been exercised.
- Module-backed engine ignores the obsolete broker TSF report path and does
  not enter the legacy 700/1500-ms inference branch. The broker recognizes the
  new capability and does not start a competing applier for that engine.
- Development builds now say `1.1.0-dev.2`, not RC1. Profile diagnostics identify
  the observed thread rather than claiming a native taskbar indicator reading.

## Current blocker and remaining work

   user-confirmed EN→RU picker tests on October 6 local time now prove that
   background TSF getters/sinks, including an activated observer client and
   language-profile notifications, miss both changes. This is an implementation
   blocker, not a missing user confirmation. The subsequently authorized
   **isolated** DLL experiment now received real EN→RU native-picker events
   through TSF inside the test window's own thread. A message-only observer
   failed. The user then explicitly authorized integration and tests in working
   applications on **both devices**; do not ask for this permission again.
   Module transport, the same-bitness hook owner, resource packaging and an
   optional engine branch are now implemented and fixture-tested on both hosts.
   Still missing: connect the ordinary startup to this branch after completing
   SYSTEM foreground handling and a protected x86 hook host (the x64 owner

   real working applications. The current component intentionally does not
   initialize a TSF client on their behalf. Deployment remains closed.

   prove manual-after-Caps, focus, stale completion and fast alternation races.

   fallback without losing existing pairing/certificates.
4. Merge screensaver suppression into the ordinary process plus recovery
