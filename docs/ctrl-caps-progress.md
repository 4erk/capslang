# Ctrl+CapsLock — работа над выделенным текстом

История разработки dev.3, продолженная в [журнале RC3](1.1-rc3-progress.md).
Актуальный выпуск — [1.1.0](release-1.1.0.md), результаты установки —
[журнал доставки](1.1-delivery.md). Утверждения ниже относятся к своим этапам.

Уточнено пользователем: направление определяется выделенным текстом, а не
текущим языком клавиатуры. Латинский текст преобразуется в русский, русский
в латинский; смешанный — в обе стороны без смены общего языка.
После подтверждённой одноязычной замены обновлять общий язык; сохранять выделение,
регистр и несопоставленные Unicode-символы. Без выделения — без изменений.

Реализованы модель клавиш и физическое соответствие EN/RU, отдельная команда
в защищённом SYSTEM-канале, ограниченная команда редактирования в оконном
модуле и ожидание результата перед созданием пользовательского выбора языка.
Операция выполняется в потоке приложения без буфера обмена и синтетического
ввода. Команда привязана к окну фокуса и сроку действия; повтор её доставки
не выполняет вторую замену. Неизвестный, парольный или read-only ввод должен
отклоняться. В TSF неизвестные сведения input-scope отклоняются консервативно.

Проверено: 511 проверок ядра, 62 проверки протокола профиля,
131120 проверок SYSTEM-протокола, 237 Windows-интеграционных проверок
(10 новых: замена в настоящем EDIT, обратное преобразование, выделение,
пустое выделение, read-only, password, неизменный буфер), 348 проверок
приложения. Старые IPC/TLS/сетевые тесты прошли. Собраны x64/x86 модули.

Не подтверждены: полный путь физического Ctrl+CapsLock через SYSTEM и MWB,
TSF-редактирование в Opera, применение языка на втором устройстве после
замены, быстрые повторные команды и смена выделения во время задержки.
Синхронный TSF edit-session может быть отклонён приложением; асинхронное
редактирование пока не реализовано. Это не готовый релиз или установка.

`tests/selection_live_fixture.cpp` — ограниченное отдельное приложение для
ручного теста. Его окно действует 150 секунд; не ведёт журнал содержимого.
Пользователь подтвердил работу в этом окне. Его hook действует только при
фокусе в собственном тестовом окне: пользовательский отказ в Opera в том же
прогоне не проверяет браузерный редактор и не доказывает отказ TSF. Для Opera
нужна отдельная проверка полного модуля/контроллера.

Следующий временный запуск полной сборки сначала завершался ERROR_BUSY:
на ноутбуке обнаружена работающая пользовательская 1.0.0, которую новый
engine проверяет до старта. Штатные --prepare-install / --complete-install
установленной RC2 завершились успешно; старый EXE сохранён, RC2 восстановлена.
Порядок остановки в проверочном координаторе исправлен: сначала broker,
потом engine, чтобы broker не запускал engine повторно во время обслуживания.
При наличии штатной SYSTEM-службы координатор проверяет её точный путь,
учётную запись и режим запуска; временно останавливает и затем восстанавливает
её вместе с прежними задачами. Рабочий EXE и сопряжение проверяются после теста.

Браузерный тест запущен с диагностическим SHA-256
`57DD9990EC8F4CB19D3861D0C6B3F843068A27900E88EA90ADCBA958DF235161`:
ядро, hook и профиль готовы. Пользователь подтвердил редактирование в Opera;
после этого уточнил правило направления. Этот результат не подтверждает новую
реализацию направления. Диагностический прогон завершился с кодом 0,
рабочая RC2 и сопряжение сохранены, прежние роли восстановлены.

Новая реализация направления: 515 проверок ядра, 62 проверки протокола,
237 Windows-интеграционных проверок и полный RuntimeTestsOnly прошли.
Результат успешного редактирования передаёт только EN/RU/смешанный текст
через код результата; протокол профиля обновлён до версии 4. Общий язык
меняется только после успешной одноязычной замены и при актуальном поколении.
Диагностический EXE: `E9D554CA4F5374398E346BE2641394C5DC622BFB9FFCA2E01EB0825D2D6F3A9B`.
Первый запуск этого EXE не состоялся: копирование EXE без извлечения новых
модулей оставило engine без ожидаемого пути DLL (код 3). Повторный запуск
использует штатный --profile-probe-stage после завершения очистки первого.
Это ещё не установка или физическое подтверждение нового правила в Opera.
Повторный запуск после штатного извлечения модулей готов: fresh=true,
engine_error=0, profile_confirmed=true, SYSTEM-hook готов. Координатор PID
22032 на ноутбуке ограничен 180 секундами и автоматически восстанавливает RC2.
